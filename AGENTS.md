# Context Management

Before starting work:
1. Read docs/PROJECT_STATE.md
2. Read relevant architecture documentation docs/ARCHITECTURE.md
3. Read the buildout plan docs/ROADMAP.md (progress + next ticket)
4. Read current task if one exists docs/CURRENT_TASK.md

During work:
- Keep CURRENT_TASK.md updated.
- Do not silently change architectural assumptions.
- If a significant decision is made, record it in docs/DECISIONS.md.
- Any new feature/seam that only exists in development must be recorded in
  docs/PRODUCTION_CHECKLIST.md (with its production action and verification).

Before finishing:
1. Verify the implementation.
2. Update PROJECT_STATE.md.
3. Update CURRENT_TASK.md.
4. State what remains unfinished.
5. State the next logical action.

The documentation must reflect reality, not the intended state.
